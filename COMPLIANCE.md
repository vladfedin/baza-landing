# Compliance: 152-ФЗ для лендинга Ролебазы

Чек-лист действий, не покрытых кодом, для оператора-самозанятого.

## 1. Заполнить плейсхолдеры в legal-документах

В файлах `www/privacy.html`, `www/consent.html`, `www/marketing-consent.html`, `www/terms.html` и `www/index.html` (футер) подставить реальные значения вместо:

| Плейсхолдер | Значение для самозанятого |
|---|---|
| `{{OPERATOR_NAME}}` | Полные ФИО (например: «Иванов Иван Иванович») |
| `{{OPERATOR_STATUS}}` | «Самозанятый — плательщик налога на профессиональный доход» |
| `{{OPERATOR_INN}}` | ИНН (12 цифр для физлица) |
| `{{OPERATOR_ADDRESS}}` | Почтовый адрес для корреспонденции — можно указать только email, если регистрация по адресу не желательна, но почтовый адрес — стандартное требование |

ОГРНИП у самозанятого нет — оставить только ИНН.

Поиск всех плейсхолдеров: `grep -rn "{{OPERATOR" www/`.

## 2. Завести почтовый ящик для запросов субъектов

Создать `privacy@rolebaza.ru` либо настроить алиас на существующий ящик. Этот адрес фигурирует в политике, согласиях и футере. Срок ответа на обращения — **30 дней** (ч. 1 ст. 20 152-ФЗ).

## 3. Подать уведомление в Роскомнадзор

Через [pd.rkn.gov.ru/operators-registry/notification/](https://pd.rkn.gov.ru/operators-registry/notification/), вход через ЕСИА.

В уведомлении указать:
- Реквизиты оператора (см. п. 1)
- Цели обработки: формирование листа ожидания, информационные рассылки (с согласия)
- Категории субъектов: пользователи Сайта (физические лица)
- Категории ПДн: имя, email, IP, User-Agent, источник перехода, метаданные согласия
- Перечень действий: сбор, запись, систематизация, накопление, хранение, уточнение, извлечение, использование, передача обработчикам в РФ, обезличивание, удаление
- Срок обработки: до отзыва согласия либо 3 года с последнего взаимодействия
- Меры защиты: HTTPS/TLS, ограничение доступа, резервное копирование, использование российских хостинг-провайдеров и сервисов рассылки
- Трансграничная передача: не осуществляется
- Лицо, ответственное за обработку: сам оператор (для самозанятого ответственный совмещён с оператором — допустимо)

**Штраф за неподачу для физлица-самозанятого по ч. 10 ст. 13.11 КоАП — 5 000 – 10 000 ₽** (для юрлиц 100–300 тыс., для самозанятого применяется санкция как для гражданина).

## 4. Внутренние документы (упрощённые для самозанятого)

Самозанятый без работников освобождён от ведения большинства внутренних документов, обязательных для юрлиц. Достаточно:

- **Политика на сайте** (`www/privacy.html`) — публикуется, как сейчас.
- **Текст согласия** (`www/consent.html`, `www/marketing-consent.html`) — публикуется.
- **Журнал учёта обращений субъектов** — простая таблица (Google Sheets, файл .ods): дата получения, отправитель, существо, дата ответа, результат. Хранить 3 года.
- **Журнал учёта согласий** — фактически уже ведётся в БД (таблица `landing_waitlist_leads` хранит email + IP + UA + timestamp; после Фазы 2 будет также `consent_pdn_at`, `consent_marketing_at`, `consent_policy_version`). Этого достаточно.
- **Журнал инцидентов** — заводится при первом инциденте.

Приказ о назначении ответственного, Положение об обработке ПДн в полной форме — НЕ обязательны для самозанятого без работников. Указание ответственным самого оператора в Политике на сайте достаточно.

## 5. План действий при утечке (24/72 часа)

Заранее заготовленный сценарий для штатной готовности.

**Час 0 — обнаружение.** Зафиксировать дату и время обнаружения, источник информации, предположительный объём затронутых субъектов.

**Час 0–2 — локализация.** Закрыть точку утечки (заблокировать доступ, отозвать ключи, выключить уязвимый компонент). Сохранить логи.

**До 24 часов — первое уведомление РКН.** Через [pd.rkn.gov.ru](https://pd.rkn.gov.ru) (раздел уведомлений об инцидентах). Указать:
- Дата/время обнаружения
- Категории и предполагаемое количество затронутых субъектов
- Состав ПДн в утечке (для лендинга — email + имя + IP + UA)
- Предполагаемые причины
- Принятые экстренные меры

**До 72 часов — детальное уведомление РКН.** Результаты внутреннего расследования: фактическая причина, лица/системы, действия которых привели к инциденту, принятые корректирующие меры, оценка вреда субъектам.

**Уведомление субъектов.** Email-рассылка по затронутой выборке: что произошло, какие данные затронуты, что делать пользователю (например, сменить пароли на ресурсах, где использовался тот же email-адрес — хотя на лендинге паролей нет).

Шаблоны уведомлений РКН: образцы есть на [data-sec.ru](https://data-sec.ru/) и в публикациях Pepeliaev Group. Заранее заготовить пустой Word-файл с разделами по приведённой структуре.

## 6. Технические меры (фактически реализовано)

Для подтверждения соблюдения ст. 19 152-ФЗ:

- HTTPS принудительно (см. `devops/nginx.land.rolebaza.ru.conf`, редирект 80→443).
- Бэкенд `beta.rolebaza.ru/api` — на серверах в РФ (требование локализации ст. 18 ч. 5).
- БД PostgreSQL c регулярным резервным копированием.
- SMTP-рассылка через российский сервис (nodemailer + SMTP в РФ — фактически в `magicorp-vtt/server/src/services/email.service.ts`).
- Аналитика — только Яндекс.Метрика, после согласия пользователя через cookie-баннер.
- Антифрод/защита от спама — honeypot-поле `website` в форме waitlist.

Этого достаточно для самозанятого без публичных API-ключей и без работников с доступом к данным.

## 7. Регулярные действия

- **Ежеквартально:** проверять актуальность реквизитов в Политике (например, при смене адреса) и публиковать новую редакцию с пометкой «Дата редакции».
- **Ежегодно:** проверять, не появились ли новые требования по 152-ФЗ (последние крупные правки — ФЗ-23 от 28.02.2025 о локализации, ФЗ-420 от 30.11.2024 об оборотных штрафах, ФЗ-156 от 24.06.2025 об отдельной форме согласия).
- **При каждом изменении формы или состава собираемых данных:** обновить раздел 4 Политики и текст согласия, версию `POLICY_VERSION` в `main.js`.

## 8. Что выходит за рамки минимума, но рекомендуется

- Завести отдельный простой реестр обработчиков (хостинг, SMTP) с реквизитами и типом обрабатываемых данных — на случай запроса РКН.
- При первом миграционном переезде на VPS / при смене SMTP-сервиса — обновить раздел 9 Политики (перечень обработчиков).
- При появлении интеграций с зарубежными сервисами — отказаться или подать уведомление о трансграничной передаче (10 рабочих дней на рассмотрение).
